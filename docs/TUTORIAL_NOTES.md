## 一句话定位
用一个微信小号，接 GeWe 第三方协议，在**自己的**微信群里放一个会聊天、会统计、会玩小游戏的 AI 群友；默认只演练不发送，三道闸全打开才会说话。

## 必须写在开头的风险（原话可直接用）
- GeWe 不是微信官方接口，违反《微信软件许可及服务协议》，有封号风险。
- 只用小号，只在自己的群里用。
- 不加人、不群发、不做营销。
- 能用官方方案就用官方：微信 ClawBot 插件（2026-03 推出，只能单聊、不能进群）、企业微信（只在企业微信群里）。只有「必须进普通微信群」才值得用 GeWe。

## GeWe 是什么（科普段）
- 第三方微信协议服务（geweapi.com），用 iPad / Mac 端协议让一个微信号在云端「执行节点」上保持登录，对外给 HTTP API：发文字、图片、语音、链接，查群成员等。
- 收消息靠 Webhook：微信里有新消息，GeWe 把 JSON POST 到你填的公网地址。
- 计费按节点，注册默认 7 天试用并自动生成一个 Token（请求头 `X-GEWE-TOKEN`）。
- 官方文档：快速开始 doc.geweapi.com/doc-3146201、风险说明 doc-6356339、调试指南 doc-3146245、Webhook 说明 doc-3146208。

## 注册 / 扫码登录流程（配图建议：流程图 + 手机扫码截图打码）
1. 注册 GeWe →「令牌管理」复制 TokenId。
2. `getLoginQrCode`：第一次 appId 传空 → 返回 appId + uuid + 二维码（约 150 秒有效）。
3. 手机微信扫码确认 → 每 5 秒调一次 `checkLogin(appId, uuid)`，status=2 就是登录成功，返回 wxid。
4. 保存「appId ↔ wxid」的对应关系，后面每个接口都要带 appId。
- 本项目对应 `scripts/login_qr.py` 和 `scripts/login_check.py`：手动跑，不打印 Token，自动读写 appId 文件。

### 坑 1：appId 会变 / 不能每次新建
- 掉线后重新登录**必须带上原 appId**，不带等于新开一台设备。手机「设置 → 账号与安全 → 登录过的设备」里会出现好几个 iPad，GeWe 文档把这叫「循环掉线（越登越封）」。
- 新设备头 24 小时掉一次是正常的，用原 appId 再扫一次就能稳定。
- 如果平台还是给了新 appId，要同步改掉程序读的那个值。本项目把 appId 放在一个文件里，脚本会自动写回，程序每次请求都重新读，不用改代码、不用重启。
- 素材点：「掉线了别慌着重扫，先确认 appId 没变」。

## 回调怎么接（配图建议：架构图）
```
微信 → GeWe → POST JSON → 公网机器:8787 [relay：收下、落 SQLite、立刻 200]
                                   ↑ 本机 127.0.0.1 长轮询
                           [poller：去重 → 解析 → 路由 → 各功能] → 三道闸 + 限速 → GeWe 发送接口 → 微信
```
- 同一台公网机器上跑两个进程：relay 只管「收下、存、立刻返回」，poller 慢慢处理。
- GeWe 的硬要求：公网可访问、POST JSON、**3 秒内返回**，超时这次回调就丢了。所以一定要先存、立刻返回、后台再处理，千万不要在回调里同步调大模型。
- GeWe 推送不能自定义请求头，所以鉴权靠 URL 里的一长串随机 secret：`/callback/<secret>`。
- 设好回调后 GeWe 会先发一条测试包，要识别并跳过。
- 接口发出去的消息不会触发回调，手机上发的才会，所以「机器人自己说的话」不会回流。
- 同一条消息可能重复回调（服务重启、同步、重试），要用 appid + newMsgId 去重。
- relay 顺便当临时图床：GeWe 发图要一个公网 URL，没有上传接口。

## 跑起来的步骤（对应 README 第 4 章）
1. 在公网机器上 clone `gewe-wechat-bot` → 建 venv → `pip install -r requirements.txt -r relay/requirements.txt`。
2. `cp bot.env.example bot.env`（非密钥：发送闸、白名单、身份）；密钥写进 `/etc/gewe-wechat-bot.env`（chmod 600）。
3. 先不连微信自测：`simulate.py`、`tests/run_all.sh`、`scripts/smoke_test.py`（本地起 relay + poller + 调试回调服务，模拟消息全程走通，一条都不发）。
4. 扫码登录 → 给 filehelper 发一句自检 → 前台起 relay 和 poller → GeWe 控制台填回调地址。
5. 默认 dry-run 跑一阵看日志 → `BOT_SEND_ENABLED=1`，白名单只放一个测试群 → 配好模型 Key 后在群里 `@小助手 开启 陪聊`。
6. 想长期挂着：一句话指向 README 附录（systemd），正文不展开。

## 安全设计（可以当一节「为什么它不容易翻车」）
- 三道闸：发送总闸（默认关）→ 白名单（默认空）→ 群级功能开关（会主动说话、花额度的功能默认都关）。另外，标成观察的群硬拦。
- 全局限速：每分钟最多 40 条；同一个群两条之间随机等 2–5 秒；都能用环境变量调。
- 掉线只告警，绝不自动重登（自动重登 = 频繁换设备 = 加速封号）。
- 代码里没有加好友、自动通过好友、拉群、群发的功能。
- 密钥只在环境变量里，日志自动打码。

## 踩坑清单（每条都能单独写一帖）
1. **env 文件不能 `source`**：systemd 的 EnvironmentFile 是纯 `KEY=VALUE`。密钥里有 `& ; $` 或空格时，bash `source` 会把它当命令解释，Key 被截断或直接报错；写在值后面的 `# 注释` 在 systemd 里又会变成值的一部分。解决：注释单独一行；手动跑用逐行读取再 export 的小脚本（`scripts/with_env.sh`）。
2. **重新登录 appId 变化**：见上面坑 1。
3. **缺中文字体**：服务器默认没装 CJK 字体，Pillow 画出来的日报长图、游戏图里中文全是方块。`apt install fonts-noto-cjk`。
4. **root 属主**（属于附录的坑，正文可一句带过）：服务先用 root 跑过，data/ 里的数据库、日志全变成 root 所有，换成普通用户后读写失败、服务起不来。一开始就建专用用户；已经踩了就 `chown -R`。
5. **3 秒超时**：在回调里同步调模型，回调就会被丢。先返回再处理。
6. **新号别猛冲**：刚登录就高频发消息、加人、建群，会直接触发风控掉线。先挂几天，只被动回复。

## 可以用的数字 / 素材
- 默认限速：40 条 / 分钟，同一个群间隔 2–5 秒。
- 回调必须 3 秒内返回；二维码约 150 秒有效；掉线检查每 5 分钟一次。
- 测试：45 个单测脚本 + 1 个端到端冒烟，全部不联网、不需要任何 Key。
- 功能量：30 多个可开关的功能（规则类默认开，调模型 / 主动说话的默认关）。
